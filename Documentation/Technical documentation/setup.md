# Установка и настройка

## Установить скилл

Сохранить репозиторий в постоянном каталоге и скопировать всю папку `skills/jira-workflow` в личный каталог скиллов Codex. В актуальной [официальной документации](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills) для личных скиллов указан `~/.agents/skills`; в Windows это `%USERPROFILE%\.agents\skills`.

В уже настроенной среде скилл может быть установлен в другом каталоге, например `%USERPROFILE%\.codex\skills`. В таком случае обновлять существующую установку, а не создавать вторую копию с тем же именем. При сомнении попросить Codex назвать фактически загруженный путь `jira-workflow`.

Итоговая папка установки должна содержать:

```text
jira-workflow/
  SKILL.md
  agents/openai.yaml
  references/client-usage.md
```

Если новый скилл не появился, перезапустить Codex. Установка скилла не даёт разрешения на произвольные скрипты, изменения Jira или настройку окружения.

При первом прямом запросе Jira агент спросит путь к репозиторию клиента. В ответ указать абсолютный путь к папке с `client/` и, для операций по рабочим репозиториям, `config.json`. Для показа проектов через `GetProjects` конфиг не нужен. После проверки агент сохранит путь в `references/local-client.json` установленного скилла. В распространяемой копии этот файл отсутствует. Если папка пропала, агент запросит новый путь; автоматического поиска другой копии нет.

## Создать локальную конфигурацию

Скопировать `config.example.json` в `config.json` в корне репозитория, если рабочего `config.json` ещё нет. Существующий конфиг не перезаписывать. Пустой шаблон:

```json
{
  "schemaVersion": 1,
  "repositories": []
}
```

Для регистрации явно указать агенту абсолютный путь рабочего репозитория и разрешённые ключи проектов Jira. Например:

```text
Добавь в конфиг Jira привязку рабочего репозитория D:\Work\ExampleApp
к проекту EXAMPLE. Разрешаю сохранить именно эту привязку.
```

Эквивалентная запись после согласования:

```json
{
  "schemaVersion": 1,
  "repositories": [
    {
      "path": "D:/Work/ExampleApp",
      "jiraProjectKeys": ["EXAMPLE"]
    }
  ]
}
```

Это вымышленные значения. Не добавлять их как действующую регистрацию. Наличие ключа задачи в коммите или название папки не разрешает автоматически менять конфиг.

Один репозиторий может иметь несколько согласованных ключей Jira; один проект Jira — несколько репозиториев. При вложенных путях выбирается наиболее конкретная привязка с учётом границы каталога. Перенос, другая копия или worktree не наследуют регистрацию автоматически.

## Настроить подключение

Клиент читает переменные окружения текущего процесса:

| Переменная | Содержание |
| --- | --- |
| `JIRA_SITE_URL` | HTTPS-адрес сайта вида `https://<сайт>.atlassian.net` без дополнительного пути |
| `JIRA_EMAIL` | Email аккаунта, которому принадлежит токен |
| `JIRA_API_TOKEN` | API token, вводимый локально |
| `JIRA_CLOUD_ID` | UUID сайта для scoped-токена; для обычного токена без scopes переменная не нужна |

Токен создаётся в аккаунте Atlassian по [официальной инструкции](https://support.atlassian.com/atlassian-account/docs/manage-api-tokens-for-your-atlassian-account/). Используется Basic authentication с email и API token, не пароль аккаунта. Для токена со scopes клиент направляет запросы через `https://api.atlassian.com/ex/jira/<cloudId>/rest/api/3/`; Cloud ID сайта нельзя заменять ID организации.

Токен должен разрешать используемые операции и чтение текущего аккаунта (`myself`). Права аккаунта в проектах также должны разрешать соответствующие действия. Не выдавать права на удаление или администрирование ради настройки клиента. Подробности: [авторизация Jira REST API](https://developer.atlassian.com/cloud/jira/platform/basic-auth-for-rest-apis/).

Следующие команды предназначены для ручного выполнения в своём PowerShell. Они создают пользовательские переменные Windows; агент не выполняет их автоматически:

```powershell
[Environment]::SetEnvironmentVariable('JIRA_SITE_URL', (Read-Host 'URL сайта Jira').Trim().TrimEnd('/'), 'User')
[Environment]::SetEnvironmentVariable('JIRA_EMAIL', (Read-Host 'Email Atlassian').Trim(), 'User')
```

Для токена со scopes также установить Cloud ID:

```powershell
[Environment]::SetEnvironmentVariable('JIRA_CLOUD_ID', (Read-Host 'Cloud ID сайта').Trim(), 'User')
```

Если вместо scoped-токена используется обычный токен без scopes, удалить ранее заданный Cloud ID:

```powershell
[Environment]::SetEnvironmentVariable('JIRA_CLOUD_ID', $null, 'User')
```

Ввести токен без отображения в терминале и без самого значения в тексте команды:

```powershell
$jiraToken = Read-Host 'API token' -AsSecureString
try {
    [Environment]::SetEnvironmentVariable(
        'JIRA_API_TOKEN',
        [System.Net.NetworkCredential]::new('', $jiraToken).Password,
        'User'
    )
}
finally {
    $jiraToken.Dispose()
    Remove-Variable jiraToken
}
```

После изменения пользовательских переменных полностью перезапустить Codex, чтобы новые процессы получили окружение. Скрытый ввод защищает от отображения токена на экране; переменная окружения не является зашифрованным хранилищем секретов.

## Первое обращение

Для проверки подключения до регистрации рабочих репозиториев попросить: «Покажи доступные проекты Jira, не меняя конфиг». Агент выполнит `GetProjects`: проверит аккаунт и покажет ключи и названия проектов без чтения или записи конфигурации, создания кеша и очистки данных. Для ручного вызова использовать `pwsh -NoProfile -File <путь к client/jira.ps1> -Command GetProjects` без дополнительных параметров.

Проверить версию `pwsh` — требуется 7.5+. Затем попросить агент прочитать задачу из зарегистрированного репозитория. Для краткой информации можно явно попросить не скачивать вложения.

Пример ручной команды чтения после подстановки собственных путей:

```powershell
$jiraRoot = Read-Host 'Абсолютный путь к репозиторию клиента'
$jiraClient = Join-Path $jiraRoot 'client/jira.ps1'
$jiraWorkRepository = Read-Host 'Абсолютный путь зарегистрированного рабочего репозитория'
& pwsh -NoProfile -File $jiraClient -Command GetIssue -RepositoryPath $jiraWorkRepository -IssueKey 'EXAMPLE-13'
```

Этот пример выполняет реальное чтение Jira; запускать его только для нужной задачи и после разрешения на такое действие. Значение токена не передаётся аргументом.

## Обновление и перенос

Обновлять исходники клиента и переносимый скилл согласованной версией. В установленный скилл переносить `SKILL.md`, `agents/openai.yaml` и `references/client-usage.md`, сохраняя локальный `references/local-client.json`.

Не заменять рабочий `config.json` пустым шаблоном и не удалять `data/` при обновлении. Журнал незавершённых операций необходим для проверки результата и предотвращения повторной отправки.

При переносе клиента сохранять его `config.json` и `data/` вместе с исходниками. Обновить локальный путь установленного скилла явным указанием нового каталога. Если переносятся сами рабочие репозитории, отдельно согласовать новые привязки.
