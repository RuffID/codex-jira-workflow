# codex-jira-workflow

Локальный PowerShell-клиент и скилл для работы с Jira Cloud из Codex. Скилл определяет порядок действий и согласований, клиент выполняет ограниченный набор запросов Jira REST API.

## Возможности

- Показ доступных проектов и проверка подключения без регистрации репозиториев и записи конфигурации.
- Чтение задач и всех доступных комментариев, скачивание вложений для анализа.
- Добавление отдельного текстового комментария без вложений с проверкой результата при обрыве связи.
- Списание времени с отметкой `[Codex]` и автоматическим уменьшением оставшейся оценки.
- Смена статуса через актуальные переходы задачи.
- Создание задач после согласования конкретного содержания.
- Связывание задач при создании или отдельной операцией с выбором типа и направления.
- Загрузка файлов и картинок с размещением ссылок в описании или новом комментарии; сохранение существующего оформления описания.
- Вставка уже загруженного изображения в тело нового комментария через `PrepareImageComment`.
- Вставка изображения в описание с выравниванием слева и шириной по области описания.
- Дополнение описания задачи текстом без вложений с сохранением прежнего содержимого и защитой от перезаписи чужих изменений.
- Кеш справочников, локальный журнал операций и проверка результата при обрыве соединения.
- Автоматическая очистка устаревших локальных снимков и вложений.

Работа разрешена только для явно зарегистрированных рабочих репозиториев. В остальных проектах скилл не предлагает Jira или учёт времени. Конфигурация изначально пустая; регистрация требует явного согласования пути и ключей проектов Jira.

## Требования

- Windows и PowerShell 7.5 или новее (`pwsh`). Windows PowerShell 5.1 не подходит.
- Локальная среда Codex с доступом к файлам и разрешённым запуском клиента.
- Jira Cloud, API token и необходимые права на задачи, вложения, списание времени и переходы. Для списания в Jira должен быть включён учёт времени.

Дополнительные PowerShell-пакеты не требуются. Jira Server и Data Center этот клиент не поддерживает.

`PrepareImageComment` принимает ID изображения из вложений той же задачи. По ID исходного комментария можно перенести ширину и выравнивание изображения. [Вставка изображения в комментарий](Documentation/Technical%20documentation/README.md#изображение-в-комментарии)

## Начало работы

### Установка через Codex

Сохраните репозиторий в постоянной папке, откройте её в Codex и отправьте этот промпт:

```text
Установи в мой Codex скилл jira-workflow из локальной копии репозитория codex-jira-workflow и дай готовые команды PowerShell для подключения к Jira Cloud.

1. Используй абсолютный путь к корню открытого репозитория. Если он неизвестен, спроси, где находится моя локальная копия.
2. Прочитай Documentation/Technical documentation/setup.md и skills/jira-workflow/SKILL.md. Скопируй skills/jira-workflow в мой личный каталог скиллов Codex. Если скилл уже установлен, обнови существующую копию. Проверь структуру клиента и сохрани абсолютный путь к его репозиторию в clientRepositoryPath файла references/local-client.json установленного скилла. Если config.json отсутствует, создай его из config.example.json. Существующий конфиг сохрани. Привязки рабочих репозиториев я согласую отдельно.
3. Дай один готовый блок команд для ручного запуска. Команды должны запросить HTTPS-адрес Jira Cloud вида https://company.atlassian.net, email владельца токена и токен. Сохрани значения в пользовательские переменные Windows JIRA_SITE_URL, JIRA_EMAIL и JIRA_API_TOKEN. Для ввода токена используй Read-Host -AsSecureString. Удали ранее заданную пользовательскую переменную JIRA_CLOUD_ID для подключения с токеном без scopes. Я выполню эти команды самостоятельно.
4. Дай ссылку на страницу создания API-токена Atlassian и укажи, что для этой настройки нужен обычный API token без scopes. Если подключение настраивается под администраторским аккаунтом, используй email этого аккаунта. Токен я введу локально в PowerShell. Не проси присылать его в чат.
5. Укажи, куда скопирован скилл и какой путь к клиенту сохранён. Напомни, что нужен PowerShell 7.5+ (pwsh) и что после настройки переменных нужно полностью перезапустить Codex. Для проверки подключения предложи отправить отдельный запрос «Покажи доступные проекты Jira, не меняя конфиг».
```

### Ручная установка

1. Сохранить репозиторий в постоянной локальной папке.
2. Установить `skills/jira-workflow` в каталог личных скиллов Codex.
3. Создать локальный `config.json` из `config.example.json`.
4. Настроить переменные окружения Jira, вводя токен локально.
5. При первом прямом обращении к Jira указать агенту путь к этому репозиторию.
6. Явно согласовать привязку рабочего репозитория к ключам проектов Jira.

Пошаговые действия и команды: [настройка](Documentation/Technical%20documentation/setup.md).

После настройки можно просить:

```text
Посмотри задачу EXAMPLE-13 и её вложения.
Покажи доступные проекты Jira, не меняя конфиг.
Спиши 10 минут в EXAMPLE-13: исправление расчёта.
Переведи EXAMPLE-13 в «Ожидание ОС».
Добавь в EXAMPLE-13 краткий комментарий, на чём остановилась работа.
Подготовь новую задачу в проекте EXAMPLE.
Свяжи EXAMPLE-13 с EXAMPLE-14 типом «связана с».
Добавь screenshot.png в EXAMPLE-13 новым комментарием.
Добавь details.pdf именно в описание EXAMPLE-13.
```

`EXAMPLE` — вымышленный ключ для примеров, действующую привязку он не создаёт. Перед изменениями агент проверяет разрешения, параметры и доступные действия.

## Состав репозитория

```text
client/                          PowerShell-клиент и внутренние модули
skills/jira-workflow/             Переносимый скилл без персонального пути
config.example.json              Пустой шаблон привязок
Documentation/                   Инструкции и техническое описание
```

Локальные `config.json`, `data/`, `client/tests/`, `.vs/`, `references/local-client.json`, логи, временные файлы и `.env` исключены через `.gitignore`. Все сохраняемые клиентом данные задач находятся в `data/`. Исходники локальных тестов в распространяемую копию не включаются.
